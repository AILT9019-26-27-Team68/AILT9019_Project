01 · The problem

Students need a mirror, not another chatbot.

Academic pressure, irregular sleep and lifestyle stress often show up as a vague feeling that things are slipping. General-purpose chatbots can produce reassuring text, but they have no calibrated notion of academic risk and no consistent way to compare a student's week with their peers.

Counselling is valuable but scarce, and many students are not ready for a conversation. The project asks a narrower question: can a small, auditable model give a student a private, structured starting point for reflection — and know when to point to a human?

It is for HKU students reflecting on study, sleep, stress, attendance, extracurriculars, exams, part-time work and age. It is not for diagnosis, mental-health assessment, academic decisions or emergency response.

02 · The pipeline

From eight values to a page-by-page read.

The model that predicts is separate from the model that writes. The LLM never sees raw numeric inputs — only the risk tier, score, bands, categorical signals and a page contract.

03 · What we built

A full path, not a prompt wrapper.

01

Random Forest + peer bands

A scikit-learn pipeline trained on 1,000 student records, with stratified 80/20 evaluation, class-weighted search, a tuned 0.51 threshold and four display tiers. Numeric values become z-score bands; categoricals become qualitative signals.

02

Validated Express → FastAPI path

No free-text fields. The API accepts exactly five numeric and three categorical fields, enforces ranges and allow-lists, and rejects malformed or injected payloads before inference.

03

Page-contract coaching

A server-side pattern picker and prompt contract turn one LLM reply into a 5–8 page result deck. A structured crisis rule routes to a CEDARS-aware template; ordinary cases are told not to mention CEDARS.

04

Deck, fallback and MCP

A trilingual scroll-snap deck, a visible fallback when live advice fails, and two FastMCP tools (predict_risk, get_advice) that wrap the same core path.

05 · Responsible by design

The limits are part of the product.

  • No free text. Only eight structured fields; no place to paste a prompt or personal story.
  • No persistence. No database, accounts, cookies or local storage. The last advice is held in memory only for the session.
  • Bands, not raw numbers. The LLM receives the tier, score, z-score bands and categorical signals — not names, IDs or raw numeric inputs.
  • Crisis routing. Extreme stress + minimal sleep selects a CEDARS-aware prompt; the UI also shows a fixed support line.
  • Honest fallback. If the LLM fails, the app shows a stored safety message instead of pretending the model ran.
  • Not clinical. The interface and README state that this is not diagnosis, counselling or an academic decision.

06 · Reproduce

Run the same path locally.

Clone the public repository, create the Python environment, add a Bailian API key to .env, install the Node packages and start all three services. The README has the exact commands, troubleshooting and the fixed test set.

Repository Setup guide 
git clone https://github.com/AILT9019-26-27-Team68/AILT9019_Project
cd AILT9019_Project
python -m venv .venv
.venv\Scripts\Activate.ps1   # Windows
pip install -r python/requirements.txt
npm run install:all
npm run dev                  # PY :8000 · API :5000 · WEB :5173
